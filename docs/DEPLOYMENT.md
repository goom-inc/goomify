# 公開・運用メモ

## 現状

コード／テスト／静的公開設定を用意した段階です。公開URLはまだありません。共有DB・本番認証・決済は接続されていません。

この試作の公開にSupabaseは不要です。Vercel等の静的ホストを接続すれば、まず一人用体験だけを公開できます。商用事業の試作を無料・非商用プランに当然に載せられるとは判断しません。料金と適用条件の確認、必要な課金への同意を先に行います。

## Vercelでの設定

- リポジトリ：`goom-inc/goomify`
- 試作ブランチ：`feat/worlds-playable-prototype`
- Framework：Other
- Build：`npm run build`
- Output：`dist`
- Install：依存関係なし（`vercel.json` に設定済み）
- 環境変数：なし。APIキーは不要。

まずプレビューとして公開してURLとログを確認します。独自ドメイン、課金、本番切替は未実施です。ルートはハッシュを使うのでSPA用の書き換えは不要です。既存の本番プロジェクトやドメインは変更しません。

## 公開後に確認すること

公開先でHTML／CSS／JavaScriptが正常に読み込めること、CSP／Permissions-Policy等のHTTPヘッダー、HTTPS、実際のlocalStorage保存と再読み込みを確認します。iPhone SafariとAndroid Chromeの実機操作、画面回転、キーボード、低速回線、リロード、複数タブも確認します。今回の環境内テストで完了したとは扱いません。

プロフィールや投稿を入力しても、ネットワークに送られないことをブラウザのNetworkで確認します。認証・決済と誤認しないよう、体験版表示を削除しないでください。

## 更新・停止・復旧

更新は開発ブランチとレビューを通して行います。プレビューの確認が済んでから本番対象ブランチへの反映を判断します。問題があればホスト側で直前の正常なデプロイへ戻すか、配信を停止します。課金停止は配信停止とは別なので、ホスト側の請求・プランを確認します。

この版の記録はユーザー端末内にあります。サーバーバックアップはありません。JSON書き出しはできますが、復元インポートは未実装です。保存形式を変更する更新では移行処理が必要です。

## 共同プレイへの次段階

現時点では設計メモであり、実装済みの一覧ではありません。

1. Supabase等の認証とPostgreSQLを導入し、参加権・世界・メンバー・日次行動・履歴・投稿・通報を分離。
2. 行動受付をサーバーAPI／DBトランザクションに移す。認証・参加権・役割・締切を毎回確認し、`開催ID + 利用者ID + 日`の一意制約を設定。クライアントから結果や加算値を受け取らない。
3. RLSで世界の境界を守る。秘密鍵はサーバーのみ。開催者にも秘密行動・決済権限を無制限に渡さない。
4. 締切集計は世界・日ごとに冪等に確定。二重実行・途中失敗・同時参加・退会・返金との競合を試験。
5. 通報を運営に届ける処理、対応履歴、レート制限、データ削除・バックアップ・復旧試験を追加。
6. AIは確定結果を文章化するだけに限定。失敗時は定型文で進行。モデルの出力に決済や状態変更の権限を与えない。
7. 決済はテストモードから始め、署名済みWebhookと冪等性で参加権を付与。参加枠の競合、返金・送金・取消・残高不足を検証。
8. 利用規約・プライバシー・年齢と安全対応・商用プラン・運営体制を確認後、有料公開を判断。

`connect-src 'none'` はこのローカル試作に合わせたCSPです。本番接続時は必要な接続先だけを許可する設定へ変更します。単に `*` へ広げることはしません。
